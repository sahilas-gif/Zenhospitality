Abstract

Zen World Hospitality is a Mumbai travel and accommodation business. Enquiries used to arrive by phone, personal WhatsApp chats, and online travel agencies that charge 15% to 25% per booking. This project is the company website: a showcase for hotels, domestic tours, company travel and cars, with every enquiry sent to the sales team on WhatsApp and stored for the admin. The site runs on shared cPanel hosting.

This draft describes the site on 14 October 2026. The public pages and the API are on https://zenhospitality.in. Since the first draft I have added Search Console, a sitemap, robots.txt, hotel pages, a contact form, a trip planner and a chat button. Mr. Raj Kumar says the site has brought in more than 10 calls and about 5 bookings, and about Rs 20,000 in profit. That is his figure. I did not count it from the enquiry table. International tours and flight ticketing still say Coming Soon.

1. Introduction

1.1 Client and business context

Zen World Hospitality works in two segments. The first is company travel: stays, meetings and events, invoiced through Zen. The second is leisure: partner hotels and domestic tours, including Kerala, Goa, Gujarat, Mumbai, Uttar Pradesh, Maharashtra and the Chardham. Bookings are confirmed by the Zen team. The only public booking number is +91 88280 15060. The public email is connect.zenworld@gmail.com.

1.2 Problem statement

The business had no single catalogue. Online travel agencies take a commission on each reservation. Leads from social media had nowhere verified to land. Customer details sat in personal chats. An earlier WordPress theme on the same budget host was slow and did not match the dark-and-gold brand, which is why the project is a custom build.

1.3 Objectives

  1. Build a responsive showcase for hotels, tours, company travel and transport.
  2. Send enquiries to WhatsApp and store them for the admin.
  3. Let the client add and edit hotels and packages without a developer.
  4. Keep yearly hosting and domain costs under Rs 3,000.

1.4 Scope

In scope: the public site, lead capture, the admin portal, technical SEO, and the AI planner and chat. Out of scope, as in the proposal: a flight booking engine, online payment, live room inventory, visa processing and an SMS gateway. Payment stays offline.

4. System design (as built)

4.1 Architecture

The browser loads the React build from public_html. Paths under /api are handled by FastAPI through Phusion Passenger and a2wsgi. WhatsApp and telephone links leave the server entirely. Gemini is called with HTTPS from the API when a visitor uses the planner or the chat. The live database is a SQLite file on the server, not PostgreSQL. The first draft’s architecture figure named PostgreSQL because that was the intended production engine. The shared host is running SQLite.

4.2 Technology stack

React 19 and Vite 8 on the front. Tailwind CSS v4. FastAPI and SQLAlchemy async on the back. Passenger and a2wsgi on the host. Gemini is called with generateContent. The chat and the planner try gemini-flash-latest, then gemini-3.5-flash, then gemini-2.5-flash, and they use the first model that returns.

4.3 Data the admin can change

Hotels (name, city, locality, summary, rooms, images, optional price, publish flag), tour packages, enquiries, and page text. Hotel pages do not publish a property’s own phone or email. Prices on hotel cards can be omitted. The public line is “Get best rate”.

5. Implementation details

5.1 Lead capture

A visitor opens a hotel, a tour, or the planner and asks for a quote. The drawer collects the name and phone, posts the enquiry, and opens WhatsApp with the same details. The contact page form posts to Formspree and is delivered to connect.zenworld@gmail.com.

5.2 AI

POST /api/ai/chat answers short questions. POST /api/ai/generate-itinerary returns a day-by-day plan and stores it. If Gemini is busy, the API says so and the page offers WhatsApp. After the visitor sends the quote, the browser downloads a PDF of the plan.

5.3 SEO

https://zenhospitality.in/sitemap.xml lists the public pages and the two hotel URLs. https://zenhospitality.in/robots.txt points at that sitemap. The domain property in Google Search Console is verified with a DNS TXT record. Hotel pages are server-rendered HTML so a crawler sees the hotel name without running the React app.

7. Results reported by the client

Mr. Raj Gupta reports that, since the website went live, it has attracted more than 10 calls and about 5 bookings, generating about Rs 20,000 in profit. This is a client report for the second draft. It is not an export from the enquiry table, and the report does not treat it as one. The mechanism that matches the report is the one the site was built for: a visitor reaches a planner on WhatsApp or by phone from the page they were reading.

8. Known limits

  • International tours and flight ticketing still say Coming Soon. They are enquiry pages, not catalogues.
  • Gemini sometimes returns a high-demand error. The planner and the chat try the next model, and they show the WhatsApp line if every model fails.
  • The Gemini key is an operating cost outside the Rs 3,000 hosting plan. Rate limits stay on both AI routes.
  • Shared hosting has a small memory cap. There is no background worker.
